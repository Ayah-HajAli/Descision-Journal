# Camera & microphone permissions

Video recording uses `image_picker`, which opens the device's native
camera app to record and hands back the file — no custom camera code
needed. That native camera still requires your app to declare camera
and microphone permissions, or the OS will refuse to open it.

**Live camera capture only really exists on iOS and Android.** On
macOS/Windows/Linux/web, `image_picker` has no sandboxed camera
entitlement wired up — calling it there can crash the whole app rather
than failing gracefully (this is what "Runner quit unexpectedly"
means if you saw it: macOS's App Sandbox kills a process outright when
it touches hardware it isn't entitled to use, and that's not something
Dart's try/catch can intercept). The app now detects this itself: on
desktop, tapping "record" opens a normal file picker to choose an
existing video instead of trying to open a camera. **To actually test
live recording, run on a physical iOS/Android device or an Android
emulator with a virtual camera enabled** — not `flutter run -d macos`.

This project ships as `lib/` + `pubspec.yaml` only (no `android/`,
`ios/` folders), since those are generated by the Flutter SDK, which
isn't available in the environment this was built in. Generate them,
then add the permissions below.

## 1. Generate the platform folders

```bash
flutter create .
```

Run this from the project root — it fills in `android/`, `ios/`,
and any other platform folders around the existing `lib/`, without
touching your code.

## 2. Android — `android/app/src/main/AndroidManifest.xml`

Add these two lines inside `<manifest>`, above `<application>`:

```xml
<uses-permission android:name="android.permission.CAMERA" />
<uses-permission android:name="android.permission.RECORD_AUDIO" />
```

## 3. iOS — `ios/Runner/Info.plist`

Add these two keys inside the outermost `<dict>`:

```xml
<key>NSCameraUsageDescription</key>
<string>Decision Journal uses your camera to record a short video of you making a decision.</string>
<key>NSMicrophoneUsageDescription</key>
<string>Decision Journal uses your microphone to record audio with your decision video.</string>
```

## 4. Run it on a phone (real camera) or desktop (file picker fallback)

```bash
flutter pub get
flutter run -d <ios-or-android-device-id>   # use `flutter devices` to list them
```

On iOS/Android, tapping **"Tap to record a short video"** opens the
real camera, records (up to 90 seconds, front camera by default), and
drops you back in the app with a playable preview. You can re-record
or remove it before sealing the decision.

If you instead run with `flutter run -d macos` (or any desktop
target), the same button becomes **"Tap to choose a video file"** and
opens a normal Finder-style file picker — this is intentional, not a
bug, and it's what keeps the app from crashing on platforms where
`image_picker` has no camera implementation.

The video stays hidden (a locked tile, no playback) while the decision
is sealed, and becomes watchable again the moment it's due for reveal
— same rule as the written prediction.

Note: the file path `image_picker` returns points at the OS's
temporary cache, and the store itself is in-memory (see `README.md`),
so videos won't survive an app restart yet. If you wire up persistence
(`hive`, `sqflite`, a backend), copy the file into a permanent
directory (e.g. via `path_provider`'s `getApplicationDocumentsDirectory()`)
at save time so it isn't cleared by the OS later.
